# Tag Tournament 2 -> T7 conversion

`MovesetConverter::TTT2ToT7::Convert` (`TKMovesets2/GameSpecific/MovesetConverters/Converter_ttt2_to_t7.cpp`) turns a
TTT2 file into a T7 moveset. It runs when a TTT2 file is imported into T7, converted (`--headless convert`), or
converted further to T8. Tekken Revolution files go through the same code with their own tables (`TREVToT7`).

## Requirement and property ids

Requirements (ids below `0x8000`) and properties share one dictionary, applied to requirement rows, extra
properties and move start/end properties (`Aliases::ApplyPropertyAlias`: the id, then the parameter through the
id's value table):

1. `InitAliasDictionary` (`Converter_ttt2_to_t7_Aliases.cpp`): the hand-made table.
2. `Aliases::BuildAliasDictionary`: fills gaps between two entries that have the same offset.
3. `ApplyVotedRules`: the rules in `Converter_ttt2_to_t7_Votes.inc`, generated by `tools/vote_ttt2_t7_rules.py`. A
   rule that keeps the id adds its values to the id's table; a rule that changes the id replaces the entry.

An id without a rule passes through unchanged.

## How the rules are voted

`tools/vote_ttt2_t7_rules.py EXTRACTED_CHARS T7_DUMP_DIR OUT.json --emit Converter_ttt2_to_t7_Votes.inc` reads the
TTT2 movesets saved by the old Python TekkenMovesetExtractor (raw TTT2 ids, see [legacy-json.md](legacy-json.md))
and payload dumps of T7 movesets built from the game's files (`dump-payload-t8`). For the 34 characters in both
games (Kazuya, Jin, Heihachi, Devil Jin and Asuka from both the Wii U and PS3 copies), moves are paired by name
(about 85% of each moveset). In each pair of moves:

- extra properties starting on the same frame are aligned on their ids;
- cancels are paired by target move name and frame windows, group cancels the same way; their requirement lists
  are aligned on their ids;
- hit conditions pair when both lists have the same length, with their requirement lists;
- hitbox bytes pair position by position.

Lists are aligned with the TTT2 ids mapped through the rules known so far. Matching runs pair, and so do differing
runs of the same length, which is where a missing or wrong rule shows. A first pass uses the current rules, a second
the rules the first pass accepted.

A rule is kept when it has at least 10 votes from at least 3 characters, 80% of them agreeing. A parameter value is
converted when at least 2 characters agree on it and none disagrees. "Player (not) character id" requirements
(T7 217, 218) keep their values: the importer compares them with the file's character id, which stays in TTT2
numbering (`RetargetCharacterIdChecks`).

## Hitboxes

Each hitbox byte names a limb. `ConvertHitbox` applies the voted bytes (`VotedHitboxBytes`), then Alisa's two
entries from the old hand-made table (one character, below the vote's threshold). The old tables chose between an
"odd" and an "even" table by the byte's parity, so some entries could never apply (`0x24`, `0x26`, `0x42` sat in the
odd table); `0x1e` -> `0x16` applied everywhere although every character keeps `0x1e`. Tekken Revolution keeps the
old tables.

## Results (2026-11-18)

The converter's output compared with the game's T7 movesets, on the paired records:

| | Records | Id right, before -> after | Id and value right, before -> after |
| --- | --- | --- | --- |
| Requirements | 2,861,408 | 99.40% -> 99.68% | 89.31% -> 99.33% |
| Properties | 176,524 | 85.72% -> 98.81% | 83.59% -> 96.51% |
| Hitbox bytes | 273,532 | 97.59% -> 99.11% | |

Ids in the output that no T7 moveset uses: requirements 10.5% of uses -> 9.7%, properties 3.8% -> 1.4%.

## Left as is

- Requirements used only by Tag mechanics (tag changes `Co_Change_Kam`, `Co_ChgIn*`, `Co_runchng`, two-character
  win poses `*_wnm_*`, `*_wns_*`, Devil Jin's `Dj_GATE_*`): T7 removed those cancels, so nothing can be voted. They
  pass through unchanged (136 requirement ids, 9.7% of requirement uses).
- Move `_0x98`: `ConvertMove0x98` is right for every value whose T7 counterpart is the same across characters (77
  values). The other differences are flags T7 added to particular moves, which the TTT2 value does not carry.
- Frame data, move length, vulnerability, hit level: 97-99.9% equal; the differences are T7 changes to those moves.
- Transitions: equal by target move name, except the `Co_Dummy_*` placeholder moves, which loop on themselves in T7.
