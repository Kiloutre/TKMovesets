# Tag Tournament 2 -> T7 conversion

`MovesetConverter::TTT2ToT7::Convert` (`TKMovesets2/GameSpecific/MovesetConverters/Converter_ttt2_to_t7.cpp`) turns a
TTT2 file into a T7 moveset. It runs when a TTT2 file is imported into T7, converted (`--headless convert`), or
converted further to T8. Tekken Revolution files go through the same code with their own tables (`TREVToT7`).

## Requirement and property ids

Requirements (ids below `0x8000`) and properties share one dictionary, applied to requirement rows, extra
properties and move start/end properties (`Aliases::ApplyPropertyAlias`: the id, then the parameter through the
id's value table):

1. `InitAliasDictionary` (`Converter_ttt2_to_t7_Aliases.cpp`): the hand-made table.
2. `Aliases::BuildAliasDictionary`: fills gaps between two entries that have the same offset.
3. `ApplyVotedRules`: the rules in `Converter_ttt2_to_t7_Votes.inc`, generated by `tools/vote_ttt2_t7_rules.py`. A
   rule that keeps the id adds its values to the id's table; a rule that changes the id replaces the entry.

An id without a rule passes through unchanged.

## How the rules are voted

`tools/vote_ttt2_t7_rules.py EXTRACTED_CHARS T7_DUMP_DIR OUT.json [--cemu DIR] --emit Converter_ttt2_to_t7_Votes.inc`
reads the TTT2 movesets saved by the old Python TekkenMovesetExtractor (raw TTT2 ids, see
[legacy-json.md](legacy-json.md)) and payload dumps of T7 movesets built from the game's files (`dump-payload-t8` of
`build-disk-movesets-t7` output). With `--cemu DIR`, TKMovesets2 extractions of the Wii U game
(`TTT2_<name>.tkmvst`, uncompressed with `--headless recompress FILE OUT none`) replace the JSON folder of the same
character. The JSON lacks the move start/end property lists and the second and third cancel lists of moves; the
extractions have them. For the 35 characters in both games, moves are paired by name (about 85% of each moveset). In
each pair of moves:

- extra properties starting on the same frame are aligned on their ids;
- move start and end properties (extractions only) are aligned on their ids, with their requirement lists;
- cancels are paired by target move name and frame windows, group cancels the same way; their requirement lists
  are aligned on their ids;
- hit conditions pair when both lists have the same length, with their requirement lists;
- hitbox bytes pair position by position.

Lists are aligned with the TTT2 ids mapped through the rules known so far. Matching runs pair, and so do differing
runs of the same length, which is where a missing or wrong rule shows. A first pass uses the current rules, a second
the rules the first pass accepted.

A rule is kept when it has at least 10 votes from at least 3 characters, 80% of them agreeing. A parameter value is
converted when at least 2 characters agree on it and none disagrees. "Player (not) character id" requirements
(T7 217, 218) keep their values: the importer compares them with the file's character id, which stays in TTT2
numbering (`RetargetCharacterIdChecks`).

## Hitboxes

Each hitbox byte names a limb. `ConvertHitbox` applies the voted bytes (`VotedHitboxBytes`), then Alisa's two
entries from the old hand-made table (one character, below the vote's threshold). The old tables chose between an
"odd" and an "even" table by the byte's parity, so some entries could never apply (`0x24`, `0x26`, `0x42` sat in the
odd table); `0x1e` -> `0x16` applied everywhere although every character keeps `0x1e`. Tekken Revolution keeps the
old tables.

## Tag button cancels

Bit `0x100` of a cancel's button word is TTT2's tag button: those cancels lead to tag changes, tag-ins, tag throws
and Devil transformation by tag (199 in Jin; no game T7 moveset uses the bit). T7 has no tag button, and the T7 ->
T8 converter copies the bit, which retail T8 reads as another input: Jin's EWHF input played the tag throw
`Thrmv_2ptN00`, whose Tag-only requirement 481 the T8 converter assumes true. The converter disables these cancels
(command `0xFFFFFFFFFFFFFFFF`, as for forbidden moves). Not for Tekken Revolution (`HasTagButton`).

Ids used only in start/end lists that the vote cannot decide:

- `0x81c8` (14 uses): every paired move, in the same character and in other characters, has T7 `0x832a` instead
  (25 of 25 across all T7 movesets), the value being a per-game id (126 -> 159 on Lee's and Violet's `Vi_IKombot*`,
  53 -> 107 on Bruce's `Ba_IChicken`). Only Lee pairs with his own T7 moveset (6 votes, one character): below the
  rule's threshold.
- `0x81c7` (26 uses, Unknown's `Uj_*RHand`) and `0x8267` (37 uses, Devil Jin's `Dj_*T`): no T7 move has these
  names. `0x82ce` (1 use, Raven's `Nj_utusemi01`): the T7 move has no end property.

## Left as is

- Requirements used only by Tag mechanics (tag changes `Co_Change_Kam`, `Co_ChgIn*`, `Co_runchng`, two-character
  win poses `*_wnm_*`, `*_wns_*`, Devil Jin's `Dj_GATE_*`): T7 removed those cancels, so nothing can be voted. They
  pass through unchanged (136 requirement ids, 9.7% of requirement uses).
- Move `_0x98`: `ConvertMove0x98` is right for every value whose T7 counterpart is the same across characters (77
  values). The other differences are flags T7 added to particular moves, which the TTT2 value does not carry.
- Frame data, move length, vulnerability, hit level: 97-99.9% equal; the differences are T7 changes to those moves.
- Transitions: equal by target move name, except the `Co_Dummy_*` placeholder moves, which loop on themselves in T7.

## Projectiles (2026-11-19)

TTT2 rows are 0x88 bytes, big-endian as the game holds them (the extractor does not swap them); T7 rows are 0xa8
bytes. No move pairs them by name (TTT2 balloons `Co_IBalloon*` and Bob's cloches `Sl_ICloche*`, T7 `Co_ISyuriken`,
`Co_IGrenade`...), so the layout was aligned by hand on the 58 Wii U extractions (16 distinct rows) and the T7 game
files (371 distinct rows):

| TTT2 word (offset) | T7 field |
| --- | --- |
| 0 (0x00) | `vfx_id` (0x00) |
| 1, 2, 3 (0x04-0x0C) | `delay`, `vertical_velocity`, `horizontal_velocity` (0x18-0x20); Angel's beam row has its speed in word 2 |
| 4-9 (0x10-0x24) | `_0x24` (1 = on), `duration`, `no_collision`, `size`, `_0x34`, `hit_level` (0x24-0x38) |
| 16 (0x40) | `voiceclip_on_hit` (0x54), aligned back from the hit condition |
| 19, 20 (0x4C, 0x50) | hit condition, cancel: null or a raw Wii U pointer in the extractions (Angel row 4, Combot rows 1-2), left empty |

T7's `0x74` is set to 1 (377 of 377 T7 rows), `0x78` to twice the size and `0x7C` to `0x34` (331 of 377). TTT2 words
10-15, 17, 18 and 21-33 (two more voiceclips, balloon colour bytes 27-29...) have no known T7 field and are left out.
Tekken Revolution rows stay zeros (`ConvertsProjectiles`).

Spawn properties: TTT2 items set `0x8169`, `0x816a`, `0x816b`, `0x816c` then `0x8168` = row, as T7 items set
`0x820c`-`0x820f` then `0x820b` = row (`0x8169` = 9 like T7's `0x820c` bone 9): they map one to one (hand-made
dictionary). The T7 -> T8 converter then turns `0x820b` into retail `0x827B` (Bob: 12 spawns, other characters 3).

Old extractor folders hold zero rows; `convert-json` writes the game's rows when the folder has the game's row count
(`filled_projectiles`, see [legacy-json.md](legacy-json.md)): the 265 rows of the 61 folders equal the Wii U
extractions.

In game (retail T8, Practice, Kazuya body): Bob's converted moveset on P1, `Co_IBalloonR/Y/B` (661-663) and
`Sl_ICloche1/5/9` (2231, 2235, 2239) queued: each played and returned to stand, the game kept running. Effects: word 0 is a TTT2 item model (`0xXXYY`, the value the item moves also set in `0x81fb`-`0x81fe`: balloon `0x6d`,
cloche `0x74`), not an effect id. Neither model exists in T7 or T8, so balloons take the bouquet effect `0x23` and
cloches the grenade effect `0x08`, two of the item effects every native T8 moveset keeps (`0x3c`, `0x08`, `0x30`, `0x23`,
`0x3e`, read from the 27 T8 extractions converted to T7). Other models (Angel's `1`, Combot's `0x9101`) are kept.

In game (retail T8, Practice, Kazuya body, 2026-11-19): Bob's converted moveset on P1, `Co_IBalloonR/Y/B` (661-663)
and `Sl_ICloche1/5/9` (2231, 2235, 2239) queued. Each move played and returned to stand, and the game kept running. The
frame data panel shows the projectile's active frames, 29 to 1228 (spawn on frame 28, duration 1200). No bouquet or
grenade shows in the video, with either the TTT2 model ids or the mapped effects.

Native T7 item projectiles were checked the same way: Kazuya's T7 moveset (built from the game's files) on P1,
`Co_ISyuriken`, `Co_IThrowKnife`, `Co_IGrenade`, `Co_ICupid`, `Co_IBouquet`, `Co_IFishGun` (711-713, 743, 744, 758)
queued. They hit P2 (20 damage, knocked across the stage, with T8's hit effect), but no item is drawn in flight
either. T8 draws none of these item projectiles; what shows is the hit, and the TTT2 rows have no hit condition (the
game's balloons and cloches do not hit), so nothing shows for them. T8's own item moves (`Co_IHummer`,
`Co_IFrenchBread`...) show a held model through `0x8342`, `0x8333` and `0x832b`/`0x8343`/`0x8344`, and no T8 move
spawns the item projectile rows.
